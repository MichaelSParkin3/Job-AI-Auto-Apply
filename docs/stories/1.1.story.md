# Story 1.1: Project Scaffold & Config Loader

## Status
Review

## Story
As a developer,
I want a structured repo with a Typer CLI and config loader,
so that I can run commands and manage defaults consistently.

## Acceptance Criteria
1. Running `python app.py --help` lists `apply`, `profiles`, `config`, `history`.
2. `config init` creates `config/config.yaml` with documented defaults.
3. `.env.local` is read for OpenRouter keys without crashing if missing.
4. Required folders exist on first run: `config/`, `data/`, `.local/`, `runs/`, `history/`.
5. Precedence documented: CLI > profile > global.

## QA Results

### Review Date: 2025-09-26

### Reviewed By: Quinn (Test Architect)

### Code Quality Assessment

The initial implementation was clean and well-structured but had two medium-severity issues:
1.  Path resolution was dependent on the current working directory, making it fragile.
2.  Configuration loading could fail silently if the `config.yaml` file was corrupted.

Both issues were addressed during this review via refactoring.

### Refactoring Performed

- **File**: `apps/cli/config_loader.py`
  - **Change**: Modified `get_base_dir()` to find the project root by locating `pyproject.toml`. Replaced a broad `except Exception` with a specific `except yaml.YAMLError` that logs a warning.
  - **Why**: To make path resolution robust and independent of the execution directory, and to ensure configuration errors are visible to the user for easier debugging.
  - **How**: The `get_base_dir` function now searches upwards from its own location for a project marker. The exception handler in `Settings.load` now specifically catches YAML parsing errors and creates a log event.
