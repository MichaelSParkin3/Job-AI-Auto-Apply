# Story 2.2 — Domain Guardrails & One-Tab Policy

## Status
Ready for Release — QA Retest Passed (single-tab telemetry fix verified)

## Story
As an operator,
I want strict navigation guardrails and a single-tab policy,
so that automation cannot wander or look like a bot.

## Context Source
- Source Document: docs/prd/epic-2-stealth-browser-wrapper-profiles.md#story-22-domain-guardrails-one-tab-policy
- Enhancement Type: Hardening feature for the Browser-Use wrapper and pacing system
- Existing System Impact: Builds on Story 2.1’s Browser-Use session bootstrap to constrain navigation, pacing, and telemetry while preserving current `apply open` CLI flows.

## Acceptance Criteria
1. Browser sessions enforce an allowlist defaulting to `*.simplyhired.com`; off-domain navigations (including redirects, resource loads, and scripted requests) are blocked, logged, and surfaced to the CLI as structured guardrail violations without crashing the session. [Source: docs/prd/epic-2-stealth-browser-wrapper-profiles.md#story-22-domain-guardrails-one-tab-policy][Source: docs/prd/requirements.md#functional-fr][Source: docs/prd/technical-assumptions.md#service-architecture]
2. Attempts to open additional tabs or windows (manual, scripted, or pop-ups) are intercepted; the controller keeps a single active tab, reuses it for subsequent actions, and records a guardrail event noting the suppression. [Source: docs/prd/epic-2-stealth-browser-wrapper-profiles.md#story-22-domain-guardrails-one-tab-policy][Source: docs/prd/requirements.md#functional-fr][Source: docs/architecture/components.md#browser-use-controller]
3. Navigation and action pacing follow a top-down queue with jittered micro-waits (100–600 ms) between simple steps and a think-time pause (1–2 s) before submissions or major transitions, with overrides configurable via config/profile while maintaining stealth defaults. [Source: docs/prd/epic-2-stealth-browser-wrapper-profiles.md#story-22-domain-guardrails-one-tab-policy][Source: docs/prd/requirements.md#functional-fr][Source: docs/prd/technical-assumptions.md#service-architecture]
4. The wrapper emits structured status events (`NAVIGATE`, `BLOCKED_DOMAIN`, `NEW_TAB_ATTEMPT`, `THINK_TIME`) through the existing logging pipeline so downstream orchestration and history capture can trace guardrail activity. [Source: docs/prd/epic-2-stealth-browser-wrapper-profiles.md#story-22-domain-guardrails-one-tab-policy][Source: docs/architecture/components.md#browser-use-controller][Source: docs/architecture/api-specification-rest.md]
5. Automated tests cover domain enforcement, single-tab handling, pacing timing envelopes, and event emission—ensuring regressions are caught in CI via unit tests with Browser-Use stubs and integration tests around `apply open --dry-run`. [Source: docs/prd/epic-2-stealth-browser-wrapper-profiles.md#story-22-domain-guardrails-one-tab-policy][Source: docs/architecture/testing-strategy.md][Source: docs/prd/technical-assumptions.md#testing-requirements-unit--integration--ui--a11y]

## Implementation Outline (Draft)
- Wrap the Browser-Use client with a guardrail adapter that inspects every navigation, frame, and resource request; deny anything outside the allowlist and emit `BLOCKED_DOMAIN` events while keeping the session alive.
- Track tab handles within the controller, closing or re-routing new windows to the primary tab and logging `NEW_TAB_ATTEMPT` telemetry with suppression metadata.
- Introduce pacing helpers that inject jittered sleeps before/after high-level actions, expose overrides via settings/profile YAML, and surface effective timings in session telemetry for downstream orchestration.
- Unify guardrail and pacing events in `log_event`, ensuring CLI consumers and run-store artifacts capture the context for auditability.

### Implementation Summary (2025-10-07)
- Added `apps/browser/guardrails.py` with `NavigationGuardrails` to normalize allowlists, block off-domain URLs, suppress multi-tab attempts, and emit jitter/think-time events without breaking the Browser-Use session lifecycle.
- Extended `BrowserLaunchConfig`/`BrowserUseController` to persist guardrail+pacing ranges, inject guardrail telemetry on `open_url`, and honor `think_time` pacing for interactions.
- Enriched `Settings`, profile schema, and CLI overrides with `browser.allowed_domains` and `browser.pacing.*` keys; CLI output now returns guardrail config in the session payload and structured events land in `actions.log`.
- Documented guardrail defaults in the README + architecture components and added a PRD index callout referencing the configuration knobs.

### Implementation Summary (2025-10-08 — QA Remediation)
- Adjusted `NavigationGuardrails.block_new_tab` to keep the single active tab count accurate while recording suppressed attempts, propagating the new telemetry to navigation events.
- Added regression coverage (`test_guardrails_maintain_single_tab_count_after_blocked_attempts`) to ensure guardrail events report `tabCount=1` after blocked attempts and surface a dedicated `blockedTabAttempts` counter.

## Dev Notes
- **Guardrail scope:** Allowlist should include scheme (`https`) and subdomains under `simplyhired.com`; consider optional configuration for future partner domains without widening defaults. [Source: docs/prd/requirements.md#functional-fr][Source: docs/prd/technical-assumptions.md#service-architecture]
- **Failure handling:** Guardrail violations return recoverable errors so the CLI can continue monitoring or retry with backoff rather than crash the Browser-Use session. [Source: docs/prd/epic-2-stealth-browser-wrapper-profiles.md#story-22-domain-guardrails-one-tab-policy]
- **Pacing strategy:** Jittered waits should apply to both navigation and interaction steps, with think-time primarily before submissions or page transitions to satisfy stealth requirements. [Source: docs/prd/requirements.md#functional-fr][Source: docs/prd/technical-assumptions.md#service-architecture]
- **Telemetry contracts:** Align event names and payload keys with existing logging schema to simplify history ingestion and later analytics. [Source: docs/architecture/components.md#browser-use-controller][Source: docs/stories/1.4.run-store-redacted-logging.md]
