# Story 3.1.5 — Browser-Use 0.7.9 Migration & Compatibility

## Status
In Progress — Adapter layer and locale/guardrail updates landed; live navigation still blocked by async session readiness.

## Story
As the automation platform engineer,
I want to upgrade our Browser-Use integration to the 0.7.9 event-driven API without regressing guardrails or CLI ergonomics,
so that the SimplyHired Quick Apply flows continue to run on a supported, stealthy browser stack with current upstream fixes.

## Context Source
- Source Document: docs/prd/requirements.md#non-functional-nfr (stealth, locale/timezone stability)  
- Source Document: docs/architecture/components.md#browser-use-controller (controller responsibilities & guardrails)  
- External Reference: https://docs.browser-use.com/introduction (0.7.x migration guide & session lifecycle)
- Enhancement Type: Dependency upgrade + compatibility shim for async BrowserSession 0.7.x
- Existing System Impact: Touches BrowserUse controller, CLI telemetry payloads, profile overrides, and stealth guardrail enforcement across Epic 2 & 3 stories; requires refreshed documentation for developers who rely on 0.6-era synchronous methods.

## Acceptance Criteria
1. `BrowserLaunchConfig` continues to accept locale/timezone/viewport inputs, but the controller maps them into `env`, `Accept-Language`, and `--lang` flags that comply with Browser-Use 0.7.9 (no direct `locale`/`timezone_id` kwargs). [Source: docs/architecture/components.md#browser-use-controller][Source: apps/browser/controller.py]  
2. A synchronous-safe adapter encapsulates Browser-Use’s async session lifecycle (`start`, event bus navigation, CDP evaluation) so existing controller consumers (`apply open`, site modules, tests) can keep calling `open_url`, `wait_for_idle`, `safe_click`, and `get_page_content` without rewriting orchestration code. [Source: docs/stories/2.1.browser-use-wrapper-initialization.md][Source: apps/browser/controller.py][Source: docs/prd/requirements.md#technical]
3. Guardrails (allowed domains, keep-alive, pacing) remain enforced after the upgrade, and telemetry payloads keep previous schema keys (`event`, `profileId`, `locale`, `timezone`, `guardrailEvent`). [Source: docs/prd/requirements.md#non-functional-nfr][Source: apps/browser/guardrails.py][Source: apps/cli/utils.py]
4. Dry-run CLI flows (`python -m app apply open … --dry-run`) succeed end-to-end, opening SimplyHired search pages in 0.7.9 and logging navigation events without `BrowserSession.__init__` argument errors or focus readiness timeouts. [Source: docs/prd/epic-3-simplyhired-quick-apply-automation.md][Source: core/tests/test_apply_open.py]
5. Unit and integration tests cover the adapter behaviour (mocked BrowserSession) plus a real dry-run smoke that ensures the new lifecycle launches Chrome, navigates to SimplyHired, and respects guardrails. [Source: docs/architecture/testing-strategy.md][Source: core/tests/test_browser_controller.py]
6. Developer documentation (README + story) identifies the new Browser-Use docs location, migration gotchas (async lifecycle, default extensions, emoji logging), and steps to upgrade local environments. [Source: README.md][Source: docs/prd/next-steps.md]

## Developer Guide
- **Release Notes & Docs:** Bookmark the official Browser-Use introduction and changelog for API updates: https://docs.browser-use.com/introduction and https://docs.browser-use.com/changelog.
- **Event Lifecycle (0.7.x):** Session startup is event-driven. Useful references in `browser_use.browser.events`: `BrowserStartEvent`, `BrowserLaunchEvent`, `BrowserConnectedEvent`, `NavigationStartedEvent`, `NavigationCompleteEvent`. We wait for `BrowserConnectedEvent` (or focus) before first navigation.
- **Code Diff Hotspots:** Core adapter and launch changes live in `apps/browser/controller.py`; unit coverage updates are in `core/tests/test_browser_controller.py`, while CLI integration adjustments surface in `core/tests/test_apply_open.py`.
- **Config Touchpoints:** Locale, timezone, and guardrail overrides still flow through `apps/cli/config_loader.py`, profile YAML under `data/profiles/`, and the `BrowserLaunchConfig` dataclass.
- **Run & Validate:** Use `python -m app apply open "<search_url>" --profile default --dry-run` to verify a post-upgrade session; inspection artifacts land under `runs/<timestamp>`.
- **Windows Console Tip:** Until we sanitize upstream emoji logs, set `PYTHONIOENCODING=utf-8` (or run inside Windows Terminal with UTF-8 output) to avoid `UnicodeEncodeError` when Browser-Use emits emoji telemetry.
- **Known Benign Warning:** `SecurityWatchdog` may warn about glob patterns in `allowed_domains` (e.g., `*.simplyhired.com`); this is expected and OK for our use case.

## Dev Notes
- Adapter currently dispatches `NavigateToUrlEvent` and reuses CDP evaluate for `wait_for_idle`/`safe_click`; need to hook into Browser-Use watchdog completion so `agent_focus` becomes available before we poll DOM.
- Default extensions (uBlock, ClearURLs) triggered large downloads on first launch; disabling them (`enable_default_extensions=False`) keeps dry-run deterministic.
- Windows console UTF-8 logging remains an issue when Browser-Use emits emoji; story will track remediation guidance for developers.
- Locale/timezone now normalized via POSIX environment variables (`LANG`, `LC_ALL`, `TZ`) and Accept-Language header to satisfy stealth posture requirements without deprecated kwargs.

## Progress Notes (2025-09-28)
- Implemented synchronous adapter plus locale/timezone mapping refactor; unit suites (`pytest core/tests/test_browser_controller.py`, `pytest core/tests/test_apply_open.py`) pass locally. [Source: apps/browser/controller.py][Source: core/tests/test_browser_controller.py][Source: core/tests/test_apply_open.py]
- Added event-driven readiness wait in `BrowserSessionAdapter` that listens for `BrowserConnectedEvent` and `AgentFocusChangedEvent`, with a polling fallback. This resolved the initial "focus not ready" startup race. [Source: apps/browser/controller.py]
- Fallback CDP navigate: if event-driven navigation leaves the browser on chrome://newtab (or Google start), we now issue a direct `Page.navigate` via CDP to the target URL. [Source: apps/browser/controller.py]
- Readiness selectors updated with a new variant (`serp-2025-data-testid`) matching current SimplyHired markup; readiness now passes under live runs. [Source: sites/simplyhired/selectors/search-readiness.json]
- Quick Apply detection refined: discovery relies on selector variants to detect inline vs modal Quick Apply after clicking a job card, and saves artifacts accordingly. (Click-to-open is handled by the card click itself; no extra button click is required in current flows.) [Source: sites/simplyhired/quick_apply_discovery.py]
- Security watchdog logs a warning about glob patterns in `allowed_domains` (expected and harmless for our `*.simplyhired.com`). [Source: browser_use.browser.watchdogs.security_watchdog]
- Backup noise resolved: backups now skip cache/lock files (e.g., `Cache_Data/*`, `GrShaderCache/*`, `lockfile`) to avoid permission errors while Chrome is running; retention unchanged. You can still disable backups with `--no-session-backups`. [Source: apps/browser/session_backup.py]
- Windows CP1252 console: now coerced to UTF‑8 inside the CLI to prevent emoji-related crashes. [Source: apps/cli/main.py]
