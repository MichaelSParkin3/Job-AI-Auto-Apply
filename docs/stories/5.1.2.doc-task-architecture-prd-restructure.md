# Doc Task — Architecture & PRD Restructure for AI-Drafted Form Answers

## Purpose
Create a shared guide for the Product Owner and Architect to reprioritize upcoming work so that **AI-drafted form answers become the number-one roadmap objective**. This document captures the desired end-state workflow, required PRD adjustments, and architectural considerations needed to deliver high-quality automatic answers during Lever (and future) job application flows.

## Background & Current Gaps
- Epic 5 currently leverages the LLM solely for form planning; actual answers must exist in the profile or resume analysis results.
- Runs in `ai_autofill` mode skip unanswered fields, leading to partial completions and queue churn.
- Stakeholders now want the agent to synthesize missing answers using the user profile and resume, while keeping humans in control during review mode.
- Screenshot artifacts are temporarily optional due to recent guardrails; we must track that remediation separately so it does not block the AI answer initiative.

## Target Form-Filling Workflow (Authoritative Requirements)
1. **Use Saved Answers First** – If a field has a persisted profile answer (or deterministic override), autofill it verbatim.
2. **LLM-Drafted Answer Fallback** – When no saved answer exists, call the LLM with resume/profile context to draft a candidate response. Responses must include confidence scoring and rationale metadata for review.
3. **Full-Auto Mode Behavior** – In `auto_submit` or other no-review modes, the system may submit using LLM-drafted answers (subject to confidence guardrails defined per profile).
4. **Review Mode UX** – In review/pending modes, surface the drafted answer, confidence, and rationale in the Preview UI. Provide reviewer actions:
   - Approve and apply (form only).
   - Approve & save to profile for future reuse.
   - Edit (form only).
   - Edit & save edited response to profile.
5. **Profile Answer Evolution** – Any approved/saved responses augment the profile so Step 1 can short-circuit future drafts.

## Required PRD Adjustments (Product Owner)
- **Reorder Epics:** Introduce or elevate an epic (e.g., new *Epic 5A — AI Answer Generation & Review Loop*) placed ahead of other upcoming epics. All downstream work (decision engine, auto-submit, scheduling) should explicitly depend on this epic’s completion.
- **Revise Epic 5 / Story Tree:**
  - Split current Story 5.1 into (a) planner refinement and (b) AI answer synthesis.
  - Add user stories for reviewer UX, profile persistence, and telemetry/analytics for drafted answers.
  - Ensure acceptance criteria cover answer confidence scoring, rationale logging, and reviewer save/edit flows.
- **Update Roadmap Narratives:** Epic descriptions, success metrics, and demo scripts must highlight automated answer drafting as the MVP breakthrough.
- **Introduce Backlog Items:**
  - Privacy/PII handling for LLM prompts/responses.
  - Configurable confidence thresholds and reviewer override policies.
  - Documentation updates (user guide, troubleshooting) describing AI-drafted answers and opt-out controls.

## Architectural Tasks (Architect)
- **System Design Refresh:** Draft a focused architecture addendum describing data flow from resume/profile → LLM prompt → drafted answer → reviewer/save pipeline.
- **Service Contracts:**
  - Extend `ProfileAnswerResolver` (or introduce `AnswerOrchestrator`) to implement the Step 1/2 fallback logic.
  - Define LLM request/response schema (confidence, rationale, suggested profile tags).
  - Specify persistence updates (`profiles/<id>.yaml`, run artifacts, telemetry events such as `AI_FIELD_DRAFTED`).
- **Preview UI Contract:** Document API additions required for reviewer actions (approve/save/edit endpoints) and telemetry for confidence acknowledgement.
- **Guardrails & Governance:** Outline safeguards (model choice, token limits, redaction, opt-in flags) and integration with future decision engine confidence policies.
- **Testing Strategy:** Identify new unit/contract/e2e coverage, including deterministic fixtures for drafted answers and reviewer feedback loops.

## Implementation Sequencing Guidance
1. **Phase 0 – Planning**: Finish architecture addendum, PRD reordering, and story breakdown.
2. **Phase 1 – Core Services:** Implement answer orchestration service, extend resume/profile ingestion, add telemetry.
3. **Phase 2 – Reviewer UX:** Update Preview UI & queue workflows to display and persist drafts.
4. **Phase 3 – Auto Modes & Policies:** Wire confidence thresholds into auto-submit paths, ensure safe defaults.
5. **Phase 4 – Analytics & Continuous Improvement:** Track draft accuracy, reviewer overrides, and promote successful answers to profiles automatically when confidence is high.

## Dependencies & Inputs
- Reliable resume parsing outputs (fields, highlights).
- Profile schema extension to store per-field metadata (source, last-updated, confidence).
- OpenRouter (or chosen LLM provider) credentials and latency budgets.
- Telemetry pipeline updates to capture drafted answer lifecycle.

## Risks & Mitigations
| Risk | Mitigation |
| --- | --- |
| LLM hallucinates or fabricates incorrect data | Implement confidence thresholds, reviewer approval requirements, and rationale logging. |
| Privacy/PII exposure in prompts | Redact sensitive data; document prompt templates; allow local-only execution. |
| Reviewer overload | Provide concise UI summaries and keyboard shortcuts; batch approvals. |
| Profile pollution from accidental saves | Require explicit confirmation when saving; track history/versioning of saved answers. |
