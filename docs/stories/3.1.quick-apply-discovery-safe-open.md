# Story 3.1 — Quick Apply Discovery & Safe Open

## Status
QA Review — PASS (multi-selector coverage validated; pytest suite executed with full dependency stack)

## Story
As an applicant,
I want the agent to scan the SimplyHired results list, open Quick Apply flows safely, then resume scanning,
so that multiple applications can be staged in one run without duplication or unsafe navigation.

## Implementation Outline (Draft)
- After readiness success, instantiate a discovery helper with selector maps (list cards, Quick Apply marker/button, pagination controls) sourced from `sites/simplyhired/selectors` and profile overrides; iterate list entries synchronously, applying guardrail think-time between actions.
- For each qualifying card, open the detail pane, validate Quick Apply availability, open the modal or inline section, snapshot DOM/screenshot, then close using deterministic selectors without triggering submission; record telemetry and visited key.
- Maintain a visited registry in memory tied to the current run context; before processing a card, skip if its posting URL/job key already exists, logging `QA_SKIPPED_DUPLICATE` when encountered.
- When `--limit` is satisfied or no further candidates remain (including after pagination), write a discovery summary (`candidatesProcessed`, `visitedCount`, `paginationEvents`, `limitRemaining`) into `run.json` and CLI output to support preview UI.
- Implement pagination by querying Next/numbered controls, emitting guardrail-friendly clicks, waiting for page idle + readiness check reuse, and resuming scanning until limit met or `END_OF_RESULTS` triggered; handle failure cases by logging and aborting gracefully.
