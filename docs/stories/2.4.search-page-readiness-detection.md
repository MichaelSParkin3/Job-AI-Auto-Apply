## Implementation Outline (Draft)
- After `BrowserUseController.open_url` succeeds, invoke a readiness orchestrator that requests the page HTML (and optional screenshot), waits for dynamic content with guardrail-friendly sleeps, and passes the DOM to `SearchReadinessDetector`.
- Detector evaluates configured selectors for the results list (anchors, job-card wrappers) and detail pane (pane container, job title) ensuring counts/visibility thresholds meet expectations; fallback selectors tried in priority order with variant metadata recorded.
- On success, emit `SEARCH_READY` with counts, variant label, elapsed time, and attach readiness summary to CLI JSON/run context. On failure, perform one retry with exponential backoff; after final failure, persist HTML snapshot (and optional screenshot), emit `SEARCH_UNREADY`, and abort automation without tearing down Browser-Use unexpectedly.
- Configuration (min card count, selectors, retry timing) sourced from global config/profile overrides with CLI precedence, enabling tuning without code changes. Artifacts stored under the run directory for QA review and future analytics.
