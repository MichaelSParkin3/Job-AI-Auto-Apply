# Story 5.2 — Headful Browser-Use Auto Fill Execution

## Status
QA PASS — Domain guardrails enforced pre/post action with BLOCKED_DOMAIN telemetry; unit tests added (2025-09-30)

## Story
As an operator,
I want the CLI to drive Browser-Use in non-headless mode using the refined plan,
so that the agent visibly fills the application end-to-end without manual clicks.

## Acceptance Criteria
1. **AutoFill Executor Replays Intents** — Introduce an executor that consumes the persisted LeverAutofillPlan, translates each field intent into Browser-Use primitives (`focus`, `fill`, `select`, `upload`, `scroll`, `wait_for_idle`), and records before/after DOM excerpts per field for audit, falling back to deterministic selectors if no intent exists. **Status:** Implemented via `core/autofill/executor.AutofillExecutor` with hashed previews, selector fallbacks, and artifact capture. [Source: docs/prd/epic-5-full-ai-form-filling-assisted-submit.md#story-52-headful-browser-use-auto-fill-execution][Source: docs/architecture/components.md#autofill-executor-epic-5][Source: docs/architecture/data-models.md#leverautofillplan]
2. **Headful Session Control** — `python app.py apply plan --mode ai_autofill` (alias of `auto_review` with auto-fill enabled) must launch Browser-Use in headful Chrome, stream progress to the console (field count, current step), and persist session metadata (profile path, CDP port, window handle) to `runs/<id>/run.json` for rehydration. **Status:** Implemented in `apps/cli/main.apply_run` with `RunStore.record_browser_session` persisting session handles. [Source: docs/prd/epic-5-full-ai-form-filling-assisted-submit.md#story-52-headful-browser-use-auto-fill-execution][Source: docs/architecture/core-workflows.md#run-modes-decision-flow][Source: docs/architecture/core-workflows.md#ai-auto-fill-assisted-submit-flow][Source: docs/prd/requirements.md#functional-fr]
3. **Telemetry & Artifact Capture** — Emit `AUTOFILL_FIELD_FILLED`, `AUTOFILL_FIELD_SKIPPED`, `AUTOFILL_UPLOAD_SUCCESS/FAILURE`, and `AUTOFILL_PLAN_READY` continuation telemetry with redacted value lengths, while persisting per-field screenshots (focused crops) under `runs/<id>/autofill/screenshots/` and synchronized HTML snippets. Ensure logs avoid raw PII and reuse hashing helpers. **Status:** Implemented with redaction helpers inside `AutofillExecutor` plus CLI logging, persisting JSON summaries and artifact directories. [Source: docs/prd/epic-5-full-ai-form-filling-assisted-submit.md#story-52-headful-browser-use-auto-fill-execution][Source: docs/architecture/components.md#autofill-executor-epic-5][Source: docs/architecture/security-and-performance.md#security-requirements]
4. **Domain Guardrails & Safe Action List** — Expand Browser-Use guardrails so ai_autofill sessions only navigate Lever and approved widget domains, reject pop-ups/new tabs, and permit the curated auxiliary actions (scroll, tab switch, retry) enumerated in the plan metadata; violations emit `BLOCKED_DOMAIN` telemetry without halting the run. **Status:** Implemented — controller performs pre/post-action domain checks and emits `guardrail.browser.BLOCKED_DOMAIN`; executor skips the field and continues. Test added at `core/tests/test_autofill_executor.py::test_autofill_blocks_and_emits_guardrail_on_disallowed_domain`. [Source: docs/prd/epic-5-full-ai-form-filling-assisted-submit.md#story-52-headful-browser-use-auto-fill-execution][Source: docs/architecture/core-workflows.md#run-modes-decision-flow][Source: docs/architecture/security-and-performance.md#security-requirements]
5. **Regression Safety** — Disabling AI auto fill (no `OPENROUTER_API_KEY`, CLI `--no-plan-llm`, or profile toggles) must execute the deterministic selector path introduced before Epic 5, preserving review-mode artifacts and queue behaviour. Regression tests verify the executor degrades gracefully when headful Chrome is unavailable (skip with message) and when Browser-Use primitives return legacy responses. **Status:** Planner gating + dry-run short-circuit remain in place; Browser-Use availability fallbacks to be exercised in follow-up live runs. [Source: docs/prd/requirements.md#functional-fr][Source: docs/architecture/core-workflows.md#run-modes-decision-flow][Source: docs/stories/5.1.llm-guided-form-plan-refinement.md]
6. **Integration Coverage** — Provide pytest suites that stub Browser-Use to validate sequencing, telemetry events, artifact persistence, and guardrail enforcement without launching Chrome; include CLI integration coverage that asserts headful launch toggles environment prerequisites and respects `automation.allow_auto` profile gating. **Status:** Implemented via `core/tests/test_autofill_executor.py` and `apps/cli/tests/test_ai_autofill_command.py` harnesses (headless stubs). [Source: docs/prd/epic-5-full-ai-form-filling-assisted-submit.md#story-52-headful-browser-use-auto-fill-execution][Source: docs/architecture/testing-strategy.md#testing-pyramid][Source: docs/architecture/development-workflow.md#environment-configuration]

## Implementation Summary (2025-12-19)
- Added `core/autofill/executor.AutofillExecutor` to replay Lever intents, hash value previews, and persist screenshots/HTML artifacts under `runs/<id>/autofill/`.
- Extended `apps/cli/main.apply_run` to log `AUTOFILL_PLAN_READY`, launch the executor during `ai_autofill` runs, and store execution + telemetry payloads alongside run artifacts.
- Introduced `RunStore.record_browser_session` so Browser-Use session handles (ID, user-data-dir, CDP endpoint) are serialized into `run.json` for rehydration/QA.
- Authored unit + CLI integration tests covering executor sequencing, telemetry emission, and run-store persistence with stubbed Browser-Use controllers.
- Replaced placeholder screenshot stubs with real Browser-Use element capture, enforced artifact integrity checks, and emitted `AUTOFILL_FIELD_SKIPPED` telemetry (with redacted hashes) on selector exhaustion or screenshot failures.

## QA Findings (2025-12-19)
- ✅ **Artifact & telemetry remediation verified:** `AutofillExecutor` now relies on `BrowserUseController.capture_element_screenshot` and emits `AUTOFILL_FIELD_SKIPPED` telemetry on selector exhaustion or dry-run skips, with pytest coverage confirming hashed payloads.
- ⚠️ **Guardrail enforcement untested:** ai_autofill flows still reuse legacy guardrail scaffolding without assertions around Lever/widget allowlists or `BLOCKED_DOMAIN` telemetry, so acceptance criteria 4 remains blocked.
- ⚠️ **Safe-action list coverage deferred:** No automated scenarios confirm permitted vs. rejected Browser-Use primitives during execution; manual validation guidance required before release.

## Dev Technical Guidance
- **Session Management:** Reuse the session backup/rehydration hooks defined in Story 2.5 when launching headful Chrome so ai_autofill runs can recover from crashes without losing executor progress. [Source: docs/architecture/core-workflows.md#run-modes-decision-flow][Source: docs/stories/2.5.session-backup-and-recovery.md]
- **Environment Safety:** Validate `OPENROUTER_API_KEY` presence via config precedence and guard logs from printing the key; use feature toggles (`automation.allow_auto`, `--no-plan-llm`) to ensure deterministic fallbacks remain available for QA. [Source: docs/architecture/development-workflow.md#environment-configuration][Source: docs/stories/5.1.llm-guided-form-plan-refinement.md]
- **PII Redaction:** Apply the same hashing/truncation helpers used for planner prompts and decision logging when persisting field values, screenshots, or telemetry metadata so no raw PII leaves Browser-Use memory. [Source: docs/architecture/security-and-performance.md#security-requirements][Source: docs/stories/4.4.decision-logging-and-history-surfacing.md]
- **Action Sequencing:** Model executor logic after the Browser-Use 0.7.x update (event-driven) to avoid race conditions; wait for `wait_for_idle` or DOM confirmation before proceeding to the next field, and enforce think-time pacing to stay within Lever rate expectations. [Source: docs/architecture/components.md#autofill-executor-epic-5]
- **Guardrail Diagnostics:** When actions are blocked, log structured telemetry + run artifacts to help QA trace issues without reproducing headful sessions; reuse `NavigationGuardrails` patterns from earlier stories. [Source: docs/prd/requirements.md#non-functional-nfr][Source: docs/stories/2.2.domain-guardrails-one-tab-policy.md]
- **Testing Strategy:** Mock Browser-Use clients so unit/integration tests run in CI without Chrome; leverage pytest markers to skip live-browser tests while still asserting telemetry payloads and artifact writes. [Source: docs/architecture/testing-strategy.md#testing-pyramid]
